## Architecture
- Multipart HTTP Route Handlers derive actor identity from the existing Paipa identity cookie.
- A shared expense domain module normalizes decimal strings, timestamps, text and delete reasons; validates categories and payment-source invariants; inspects actual receipt bytes and hashes the canonical request.
- The private expense-receipts bucket is used only by server-side admin Storage calls. The browser receives bytes through an authorized no-store Route Handler, never a public or signed URL.
- Expenses stays RLS-enabled with direct table writes revoked from browser roles and service_role. The service role has SELECT only; create, replacement, and soft-delete use narrow SECURITY DEFINER RPCs with a fixed empty search_path and explicit actor/trip/member checks. Only service_role can execute those RPCs.
- Create, replacement, and soft-delete execute their relational changes atomically in PostgreSQL. Routes upload first, then call the RPC, and remove only the newly uploaded object if the database operation loses/fails. A failed compensation returns STORAGE_CLEANUP_FAILED.
- Idempotency key scope is (trip_id, created_by, client_request_id). Hashes contain normalized business fields, replacement reason where applicable, and detected receipt SHA-256. Matching retries replay only after owner/current-member authorization; former members cannot retrieve expense DTOs by retrying a key. Changed payloads conflict.
- Replacement locks the trip and expense, compares expectedUpdatedAt, writes a new child row, and soft-deletes the parent in one transaction. A scoped self-FK and one-child partial unique index enforce the history chain.
- Read access is owner/current trip member for expense lists; audit history is owner-only. Receipt access is owner, creator, or payer, including historical rows and former members.
- delete_trip locks and checks for any expense row before deletion; the table FK is a second guard. Archive remains allowed. The service-role-only E2E cleanup RPC deletes rows only for the named M2.6 E2E trip/owner fixture after its receipts are removed through Storage.
- No spent or available aggregates, UI, or M2.7 work is included.

## Domain rules
- Amount stays a decimal string through parsing and is normalized with integer cents; PostgreSQL stores numeric(12,2), constrained to >0 and <=100000000.
- Categories: transport, accommodation, food, activity, shopping, member_refund, other.
- trip_fund requires paid_by NULL. personal requires a current trip member as paid_by.
- Owners may record trip-fund expenses and personal expenses for current members. A current member may record only their own personal expense.
- Archived trips reject create/update/delete but retain reads and receipts. Delete authorizes the owner/current member and personal-expense ownership before reporting archived or already-deleted states; nonmembers receive the hidden not-found result.
- Update is replacement history; old rows and receipts remain. Delete is soft and preserves its receipt. Repeated delete returns EXPENSE_ALREADY_DELETED without changing audit fields.
- Receipt MIME is selected solely from PNG/JPEG/WebP/PDF magic bytes; max size is 10 MiB; generated object path is {tripId}/{expenseId}/{objectId}.{detectedExt}.

## HTTP surface
- POST/GET /api/trips/{tripId}/expenses: create and active list; owner may request audit history.
- PATCH/DELETE /api/trips/{tripId}/expenses/{expenseId}: replacement and soft delete.
- GET /api/trips/{tripId}/expenses/{expenseId}/receipt: actual bytes, gated by owner/creator/payer and private no-store headers.
- Client-supplied creator, receipt path, deletion fields and replacement parent are rejected.

## Verification
- Unit tests cover normalization, hash, MIME sniffing, policy mapping and upload compensation.
- SQL integration tests cover constraints, authorization, former-member replay denial, outsider/former-member delete-state hiding, service-role write revocation, replacement chain, optimistic concurrency, soft delete and trip-delete guard inside rollback-only fixtures.
- Playwright tests use real local identities, Supabase database and private Storage, verify direct table writes fail, hide deleted/archived state from outsiders and former members, and clean only IDs and objects created by that run. A real HTTP/Storage/DB failure probe confirms uploaded receipts are removed when the locked trip becomes archived before RPC commit.
- Existing M1–M2.5 suites plus lint, typecheck, unit, E2E, build and diff-check are regression gates.
